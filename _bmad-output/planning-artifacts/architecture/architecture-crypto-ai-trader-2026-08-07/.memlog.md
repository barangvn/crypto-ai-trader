- (decision) Adopt a hexagonal modular monolith with event-driven internal pipeline: one Python codebase, separate runtime roles (api, worker, trainer), shared canonical contracts, no microservices in MVP.
- (decision) Choose Python-first backend for MVP: research, ML, backtest, risk, orchestration, and API remain in one ecosystem; React dashboard stays a separate frontend only.
- (decision) Use a canonical event envelope with event_id, event_type, schema_version, correlation_id, causation_id, occurred_at, received_at, source, source_type, symbol, run_mode, quality_state, replay_clock, payload.
- (decision) Fail closed on bad data: degrade symbol health, quarantine invalid events, stop affected strategies, block new paper orders, and alert the operator while preserving evidence.
- (decision) Use FastAPI for API plus asyncio workers for market processing and a typed in-process event bus with PostgreSQL outbox instead of an external broker in MVP.
- (decision) Use PostgreSQL 18 with TimescaleDB for operational and time-series state; keep immutable model artifacts and replay bundles in object storage; avoid extra datastore classes in MVP.
